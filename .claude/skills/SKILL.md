# Gate 3 — Unit Tests

Юнит-тесты проверяют логику без внешнего мира: без сети, диска, БД и часов. Их ценность — в скорости и точности локализации: упал тест — знаешь функцию.

## Команда

```bash
npx vitest run --coverage 'src/**/*.unit.test.ts'
# jest: npx jest --coverage --testPathPattern='\.unit\.test\.ts$'
```

Держи прогон под 10 секунд. Если дольше — внутрь просочился I/O, ищи его: это уже integration-тест не на своём месте.

## Что здесь проверяется

Только `domain/` и `application/`. Все зависимости — in-memory фейки, переданные через порты. Реальные адаптеры проверяет `integration-tests-gate`.

## Разбор падений

Определи тип падения — от этого зависит, что чинить:

1. **Регрессия** — код сломан, тест прав → чини код.
2. **Изменение контракта** — поведение изменено намеренно → обнови тест и явно скажи пользователю, какое поведение поменялось.
3. **Хрупкий тест** — тест завязан на реализацию (порядок вызовов, приватные детали, точное время) → перепиши тест на проверку наблюдаемого поведения.
4. **Флак** — падает не всегда → почти всегда `Date.now()`, `Math.random()`, реальный таймер, общее состояние между тестами или зависимость от порядка. Проверь `npx vitest run --sequence.shuffle`.

Никогда не «чини» падение через `it.skip`, `--passWithNoTests`, ослабление assert'а до `toBeTruthy()` или увеличение таймаута. Пропущенный тест — это удалённый тест с иллюзией покрытия.

## Оценка качества, а не только цифры

Покрытие показывает, что строка выполнилась, а не что поведение проверено. Ориентиры:

- domain + application: ≥ 90% строк и веток
- каждый экспорт затронут хотя бы одним тестом (важнее процента)
- ветки обработки ошибок покрыты — это то, что чаще всего ломается в проде

Быстрая проверка осмысленности: возьми 2–3 ключевые функции, мысленно (или реально) инвертируй условие / замени `+` на `-`. Если ни один тест не упал — тесты пустые. По желанию: `npx stryker run` для настоящей мутационной проверки domain-слоя.

## Выход ступени

Зелёный → `integration-tests-gate`.
Красный → отчёт: сколько упало, классификация каждого падения по типам выше, что чинишь. Также сообщи: непокрытые экспорты, тесты со `skip`, время прогона.
